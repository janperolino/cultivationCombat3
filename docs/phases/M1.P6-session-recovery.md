## Recovery protocol and limits

- Join additionally returns a separate random recovery bearer credential. The adapter retains at most two reservations. At five seconds since the last accepted command/live/sync, disconnect authority control and discard the replication stream; at 35 seconds since that activity, remove the reservation. Explicit successful Leave deletes it immediately. A dropped Leave request falls back to that timeout. Actor objects/world terrain never reset when a seat is released or claimed.
- `POST /api/resume` uses the recovery bearer plus `{sessionId, sequence}`. Each newer bounded sequence rotates active bearer, trusted connection ID and authority generation, clears old input, and starts a fresh replication stream. An identical attempt returns the identical assignment while active; an older attempt is rejected. If a lost reply is retried after its new active lease expires, the browser advances to a fresh attempt. Only the latest attempt/assignment is retained. Recovery does not advance the simulation or refresh gameplay resources. Global ingress/body/origin limits also cover resume.
- The browser stores only the recovery credential, server session identity and attempt counter in per-tab sessionStorage, with memory fallback. No state import, actor ID selection, damage grant, queued input retry, persistent terrain save or reward transaction exists. Tokens never enter URLs. This remains possession-based loopback identity; cloned tab storage or stolen credentials can contend for the same reservation. Production accounts, credential security and multi-device ownership are deferred.
- Every successful recovery replaces replica/predictor/interpolator/receipt history and command sequence. Async old responses are ignored by connection identity; the adapter rechecks active bearer after body reads. Snapshot completion gates ordinary browser input, including held keys/casts during rebuild. Successful snapshot pages keep the watchdog alive; a two-second contact gap requests recovery. Prediction still pauses at M1.P5's 250ms freshness threshold. Host unavailability remains pending until it responds; a new host or expired reservation clears recovery and requires explicit Join. A lost initial Join response cannot recover an unknown credential and occupies a seat only until timeout.
- The Node process, rather than player 1's tab, owns the world. Closing either tab does not stop the authority. Process shutdown/crash loses this in-memory arena. No save opportunity is claimed because M3 persistence does not exist. Host migration is deferred. The proposed campaign host-world/character/death rules remain M0/M3 decisions; this approved local policy does not resolve them.
