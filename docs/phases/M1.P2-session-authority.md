### Spike rules

- Host configures one or two existing unique actor IDs at construction. They stay controlled even while unassigned/disconnected, preventing rival AI takeover. One client owns one actor; only trusted host calls connect/disconnect. No client ownership transfer command.
- Each connection gets a new authority-issued generation. Reconnect/transfer requires host disconnect followed by connect; old generations cannot submit commands. Sequences start at 1, must increase, and may jump at most 1024. Invalid/rejected commands never advance sequence or refresh freshness.
- Adapter passes authenticated client identity separately from payload. Command fields: generation, sequence, actorId, input. Strict JSON-shaped input accepts finite bounded movement/climb, aim, known techniques, and boolean flags only. Clients cannot set time, position, damage, realm, resources, or health.
- At most four commands accepted per client per authority tick, with one latest-input slot. Inputs coalesce before a tick; earlier casts/dodges in that slot can be superseded. Movement/aim/climb/altitude assistance persist for 15 ticks (250 ms at 60 Hz); cast and dodge requests execute at most once per accepted slot. Game cooldown/resource checks still decide success. This is input acceptance, not a promise a cast succeeded.
- Authority advances only by fixed `DT` via `step()`. At age 15 ticks input becomes neutral; disconnect immediately clears it. Neutral input stops new acceleration, climb, casts, and dodges; simulation drag and existing dodge/projectile/attack lifetimes continue. No teleport/braking or attack cancellation policy is introduced.
- Aim XY accepts [-512, 1024] to allow off-map cursor intent, Z [-128, 128]; movement/climb axes [-1, 1]. Diagonal movement is normalized by existing simulation. Target hints must name a living, different, in-range actor; authoritative target coordinates replace client coordinates when consumed. Hints that become invalid before a later tick degrade to coordinate aim without guidance.
- Shared-clock Heavenly Step uses existing M1.P1 behavior (personal dodge, no global slowdown). Browser solo still uses `World.step` unchanged. Current actors remain opponents: ally/team/friendly-fire policy is deferred, so this phase is not yet playable cooperative combat.

Acceptance: adversarial malformed/unauthorized/replayed commands cannot alter simulation; deterministic tests cover two owners, bounded intake, reconnect generations, freshness boundaries, one-shot actions, authoritative targets, and continued AI suppression. Run all tests, TypeScript check, build, and inspect emitted authority module imports.

Scope: no socket/HTTP server, dependency additions, authentication implementation, snapshots, prediction, campaign/persistence, UI wiring, or transport/hosting selection. Trusted code retains access to World; adapters must not expose it or host management APIs to clients. Transport must enforce message byte limits, parsing and connection/ingress rate limits; the bounded authority slot does not solve wire flooding. Never reuse an authority instance's generations across a recreated network session without a transport session identity. Platform, transport, persistent world ownership, production party size, team rules, recovery, and final Heavenly Step feel remain open.

Adapter starting point (trusted host code):

```ts
const authority = new SessionAuthority(world, [0, 1]);
const generation = authority.connect('connection_1', 0);
// Send the assigned actor ID and generation to this connection.
authority.submit('connection_1', {
    generation, sequence: 1, actorId: 0,
    input: { move: { x: 1, y: 0 }, aim: { x: 300, y: 250 } },
});
authority.step(); // Host schedules at 60 Hz, never from client-provided dt.
authority.disconnect('connection_1');
```

`submit` returns acceptance or a bounded rejection reason. Acceptance only updates the latest slot; it does not advance the world or guarantee an action succeeds. `tick` reports completed steps.
