## Brief

Objective: replace M1.P3's unbounded full scar observations with a versioned, ordered, acknowledged replication stream. Deliver complete join snapshots, bounded terrain pages/deltas, atomic client application, gap/resync handling, and command receipts. Read STATUS.md, WORKFLOW.md, IMPLEMENTATION_PLAN.md, M1.P3 handoff, authority, transport server/client/tests and build configuration. No applicable AGENTS.md found.

Contract: protocol and terrain schema versions, server session ID, client sync generation, and monotonically sequenced pages. A connection holds one pinned transfer and one pending response. An unchanged acknowledgment retries the exact pending response; acknowledgment advances only after client validation/application. Gaps/mismatched revisions trigger a fresh sync generation and full snapshot. Old sync generations cannot roll back the client. Initial terrain snapshots carry all cell fields, independent of matching procedural generator code.

Each page carries at most 256 cells and 64 KiB of JSON. Terrain transfers pin cell values, revision, and final actor/attack frame at one capture point; terrain changes during transfer are included in the following delta. Deltas carry latest absolute values for every cell stamped after the acknowledged revision, so repeated damage coalesces without duplicating an excavation. Apply a complete transfer atomically; show no partially rebuilt terrain with a newer actor frame. State observations remain full current actor/attack frames on final pages, with monotonic ticks; terrain is the incremental component. No historical tick replay is promised.

Command receipts report highest accepted and highest consumed input sequence. M1.P2 latest-input coalescing still applies: a consumed high-water mark does not promise every earlier command or cast succeeded. Transient visual effects are not durable gameplay events; current attack lifetimes come from authoritative frames and can still be missed between observations. No rewards/inventory exist to replicate. Reliable action/event delivery remains an explicit future protocol extension, not a claim of this phase.

Acceptance: tests for full terrain equality after late join, paging/byte limits at complete-world mutation, sparse/repeated-cell deltas, mutation during transfer, duplicate/lost/reordered pages and acknowledgments, malformed/version/session/baseline/revision failures, atomicity, deterministic recovery, and receipt monotonicity; real HTTP and two-browser verification. Preserve solo behavior and all regression checks. Update handoff/status/checklist, commit/push, stop before M1.P5. No prediction, interpolation, transport replacement, campaign/team policy, or persistent reconnect work.

## Wire and recovery details

- Join response advertises protocol 1 and terrain schema `height-field-v2`. `POST /api/sync` takes `{protocol,schema,sessionId,syncId,ack}` under the existing per-tab bearer token and 2048-byte request limit. The obsolete full-frame `GET /api/state` endpoint is removed.
- `syncId` starts at 1 and increases for an explicit fresh snapshot; first ack must be zero. Each generation starts page sequence at 1. Requesting with the previous ack retries the exact retained page; acknowledging its sequence advances the transfer. Other gaps return HTTP 409 with `resync: true`. The browser increments syncId and rebuilds. Older sync generations/pages are rejected or ignored.
- Each transfer pins a revision and final display frame. Snapshot transfers contain all 16,384 cells with complete fields; no procedural baseline/hash assumption is needed for reconstructed terrain. Deltas contain sorted absolute values for cells whose mutation stamp exceeds the acknowledged revision. Revisions can jump because intermediate mutations are coalesced. Changes during transfer remain stamped newer and follow in the next transfer.
- The replica validates all page ordering, cell identities/counts, revision continuity, and final frame/receipt/tick monotonicity before committing. Partial transfers alter neither committed terrain nor displayed state. Duplicate packets do not apply damage twice. Every transfer commits its frame and terrain together; no historical simulation replay occurs.
- Per connection memory is bounded by one complete terrain transfer (at most 16,384 rows) plus one page and one pinned display frame. Wire pages are at most 256 cells/64 KiB, including final-frame overhead. Existing two seats, 100 requests/second per connection, 200 global API requests/second, local-only binding/origin checks and leases remain. The browser fills terrain transfers at up to 40 requests/second and otherwise observes at roughly 10 Hz. Large transfers can delay displayed actors; this is recorded, not hidden by prediction.
- Receipts distinguish highest received and consumed command sequence; coalesced earlier input/action requests can be superseded. Receipt advancement does not mean a cast passed gameplay cooldown/resource checks. Duplicate commands remain rejected. Current attacks replace the prior attack arrays; ephemeral effects can be missed between samples. This phase adds no persistent reward transactions or durable event log.
