## Performance correction after user feedback

The initial visual smoke did not establish smooth frame pacing. The user reported severe lag. Instrumented the default view with a one-second FPS/render/terrain/scenery readout under Connection details. An initial browser preview showed 23 fps and 7.5ms render work (6.9ms scenery). These are observations, not a controlled hardware benchmark.

Network presentation now caches static scenery by projected depth band, keeps nearby actor bands dynamic for correct layering/transparency, reuses unchanged bands across terrain revisions, discards offscreen rasters and paints them at six pixels per world metre. Only network presentation enables this cache; original solo uses its existing path. Height terrain skips offscreen patches without discarding pending mutation stamps. Removed the extra draw on terrain-sync replies, reduced HUD updates to 10Hz and skips collapsed network diagnostic text; the main canvas is opaque.

Verified flight, attacks, warning corridors and Falling Heaven terrain damage on a separate three-skirmisher host. With two simultaneously visible game canvases, observed 35–38 fps and roughly 4.6–5.3ms render work in combat. After closing test canvases, the user's preserved completed encounter measured 60 fps and 3.7ms render work (0.5ms terrain, 3.0ms scenery). The earlier stationary live test reached 57 fps. These scenes/viewports and concurrent canvas counts differ; no universal 60-fps combat guarantee or controlled speedup ratio is claimed. Temporary performance hosts were stopped; the normal 5177 host and user's encounter state remain intact.

Validation: 165 tests pass, including two new cache regression tests for stable revisions, destructive terrain changes, offscreen raster release and deferred terrain painting. TypeScript/build/whitespace checks pass. Screenshot: [performance review](M2.P5a-performance-review.png). The in-app game was reloaded to receive the fix and recovered its player without state grants.
